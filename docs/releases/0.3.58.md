# Cypher 0.3.58 — Images in follow-up messages reach the model

## Chats

- **Every message sends its own images to the model.** Only the message
  that started a chat's Pi process sent its images as images. Later
  messages, whether the next one in the same chat or one sent while the
  agent was working, carried only each image's file path. The model saw
  such an image only if it opened the file with a tool, and sometimes it
  did not. Each message now sends its own images. Desktop and iOS already
  attach images this way, so nothing changes in how you add them.
- **Other devices see a session's current status.** Two status changes
  made at the same moment could be published in the wrong order, and the
  older one stayed in the session list until the next change. Another
  device could then show, for example, no recovery under way while one was
  running. Status changes are now published in order, and each carries the
  session's current state.

## Permissions (with Pi Runtime 1.1.0.9)

- **Subagents can ask for file access.** When a subagent's file tool was
  refused (for a symlink target, or a sensitive file under a search root),
  the refusal told it to call `request_permission`, but subagents were not
  given that tool. Any subagent whose tools include `read`, `write`,
  `edit`, `ls`, `grep` or `find` now gets `request_permission` as well.
  This covers both subagents Cypher hosts as chats and those pi-agent-squad
  starts itself.

## iOS 0.2.0 (32)

- **Long sessions open at once.** Opening a session read and laid out
  every message before showing the latest ones. A 3,000-message session
  took about a second, and each streamed update repeated the work. The
  phone now reads the session from its end, 40 messages at a time, so
  opening it and each update cost the same however long it is. Earlier
  messages load as you scroll toward the top, without moving the message
  you're reading, and "Loading earlier messages" marks the top until the
  first message is reached. The turn scrubber still lists every turn, and
  jumping to an early one loads the messages down to it.

Cut at build 1 on both desktop platforms. Pi Runtime moves to 1.1.0.9,
published after the desktop release (it still requires 0.3.54). iOS moves
to 0.2.0 (32).
