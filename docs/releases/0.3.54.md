# Cypher 0.3.54 — Smarter recovery, model-first permissions, and cards that fit

## Context recovery

- **Subagents recover too.** Context recovery now watches subagent tasks.
  A failed subagent round is restarted with context like any other chat,
  and its parent only ever sees the retried round's result.
- **A restarted turn knows what it already did.** Rewinding can't undo what
  the failed round's tools changed on disk, so a round that ran tools is now
  restarted with a short briefing on that work ("You have already done: …
  Please continue."), written in the language of your message. The recovery
  card shows it.
- **Later attempts learn from earlier ones.** From the second attempt on,
  the model writing the context sees every earlier attempt's context and how
  it failed, and is asked to rewrite rather than repeat it.
- **Leftover Pi session files are cleaned up.** Each restart used to leave a
  copy of the chat's Pi session file behind. A rewind now deletes the one it
  replaced, and deleting a chat or project deletes its session files on its
  host, subagents included.

## Permissions (with Pi Runtime 1.1.0.6)

- **The reviewing model decides first on every kind of request.** Reading or
  writing sensitive files, running a command outside the sandbox, and MCP or
  extension tools now go to the reviewing model by default, as other requests
  already did. It approves what plainly serves your request and asks you
  about the rest, including sensitive files you didn't mention, destructive
  or hard-to-undo commands, hosts and accounts you didn't name, and changes
  to the permission setup. A command it approves outside the sandbox runs
  once with no dialog. Writes to Cypher's own data always come to you.
  Settings → Permissions offers "Model first" on every row, so you can set
  any of them back to Ask.
- **More commands can be allowed for the whole chat.** "Allow for this chat"
  used to be missing for most commands agents write (anything with `$(…)`,
  variables, globs, loops or redirections). Each command now gets a sensible
  rule, such as `git push …` or `npm run build …`; risky programs like `rm`,
  `curl` and `scp` are only ever allowed exactly as written. When only one
  run can be approved, the card says why.
- **Every permission request shows as a permission card.** Requests with a
  multi-line command or reason, or asked during a slash command's turn, fell
  back to the plain question card.

## Chats

- **Tall cards stay inside the window.** A question with a long context, or
  a permission request for a long command, could run past the bottom of the
  window. The card now fits the chat column and scrolls its body.

Cut at build 1 on both desktop platforms. iOS moves to 0.2.0 (31) with the
same recovery, permission card and settings changes. Pi Runtime 1.1.0.6
publishes after the desktop release and requires 0.3.54; older apps keep
1.1.0.5, where sensitive files and commands outside the sandbox still go to
you.
