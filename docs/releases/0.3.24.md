# Cypher 0.3.24 — Open a subagent's session, @session anywhere, and Pi 0.87.1

## Subagents

- **Clicking a subagent in the inspector opens its session**, running or
  finished. A row only navigates when its run carries a child chat, and none
  ever did: pi-agent-squad spawned every `subagent` call as its own hidden Pi
  process, so there was no session behind the row to open. Runs are now hosted
  as Cypher child chats and linked as soon as the chat exists, so a row is
  navigable while the child is still working. Progress, the final answer,
  cancellation, timeouts and routed messages all go through the child chat.
- The engine advertises the bridge to Pi children as `CYPHER_SUBAGENT_BRIDGE=2`,
  so the Runtime patch engages only against an engine that has it. An older
  engine, a refused start, or a parent that is not a durable local chat keeps
  the upstream process spawn. A start whose reply was lost fails the run instead
  of falling back, so the work is never done twice.
- `StartSubagent` takes the full task as `prompt` (up to 64 KiB; `task` stays
  the row's 500-char label) and the run's messaging address, so a second
  concurrent `planner` keeps its own messages. `WatchAgentEvents` skips lagged
  events rather than ending the stream, which the parent read as a lost child,
  and no longer doubles text across the replay/live overlap.

## Composer

- **@session references sessions in any project, on any device.** The popup and
  the send-time check accepted only sessions from the current chat's space — one
  device and folder — though the chats index already listed every session in
  the profile. Candidates now rank the current project first, then the same
  host's other projects, then other devices, each by recency; the popup lists
  eight and a query narrows the rest. The subtitle names the project and device
  and marks an offline host. The current chat and temporary side chats are
  still refused.
- A session hosted elsewhere is read from its host over the relay while that
  host's presence is fresh; when the host is offline or the read fails, the
  engine's synced replica serves instead. Frames are folded until the replica is
  non-empty and quiet for 400 ms, so a backfill arrives whole, and an empty
  replica fails the send with the host error rather than silently dropping the
  reference.

## Networking

- **HTTPS and wss:// trust the system certificate store as well as the bundled
  roots.** Both TLS stacks verified against the bundled webpki roots alone, so
  behind a corporate TLS-inspecting proxy — whose CA an admin installs in the
  system store — every Edge request and relay dial failed with `UnknownIssuer`.
  The two sets are now unioned: enterprise CAs verify, and a machine whose
  system store is empty or unreadable keeps the bundled roots. `SSL_CERT_FILE` /
  `SSL_CERT_DIR` work as an override on every platform.
- This covers the Cypher binary. Pi Runtime runs on Node, which still trusts
  only its own bundle; behind such a proxy, set `NODE_EXTRA_CA_CERTS` (or
  `NODE_USE_SYSTEM_CA=1`) in the engine's environment, e.g. `~/.cypher/env` on
  Linux.

## Pi Runtime 0.87.1.1

- **Pi 0.87.1** (from 0.86.0): Claude Opus 5.5, GPT-6 Sol and GPT-6 Luna in the
  built-in catalogs, canonical session context, and the upstream fixes since.
- **pi-claude-bridge `cd64b9f`**: 0.8.0 plus a guard that refuses a prompt
  carrying Pi's own harness rather than forwarding it to the subscription path,
  and AskClaude reporting its effective defaults. Opus 5.5 now comes from
  pi-ai's catalog; Cypher's patch only keeps it at 1M context, which the bridge
  does not yet grant an unmeasured model. Opus 5.5 needs Claude Code 2.1.280 or
  newer on the host.
- pi-mcp-adapter 2.36.0, pi-better-compaction 0.7.1, pi-goal 0.54.8,
  pi-ask-user 0.15.1.
- pi-agent-squad is patched to host subagent runs as child chats (above); with
  an engine older than 0.3.24 it behaves exactly as before.

Cut at build 1 on both desktop platforms, alongside Pi Runtime 0.87.1.1. iOS is
unchanged at 0.2.0 (15).
