# Cypher 0.3.59 — Permission control asks only about dangerous commands

## Permissions (with Pi Runtime 1.1.0.10)

Who approves a command that needs more than the sandbox now depends on what
the command does, not only on where it runs.

- **Inspections run without asking.** Commands that only look, such as
  `ps`, `lsof`, `df`, `git log`, `git status`, `git diff`, `gh run list`
  and `docker ps`, run outside the sandbox on their own. Build tools are
  not inspections: they read project files that can name a program to run.
- **Local work is approved once per project.** Builds, tests, dev scripts
  and pushes to a feature branch go to the reviewing model, which remembers
  its approval for the chat. When you are asked, the card offers **Always
  in <project>** (kept for that repository and all its worktrees) or
  **Once**. Files keep their Allow for this chat option.
- **Dangerous work always asks you.** That covers publishing (a push to the
  default branch, tags, `--force`, `gh release`, `npm publish`, deploys),
  sending (mail and chat tools, `curl` with a request body), deleting
  outside the workspace, stopping processes the agent did not start,
  changes that persist (`sudo`, `launchctl`, `crontab`, `brew install`),
  secrets, and code downloaded and run. The card says what is dangerous
  about the command. **Allow for this task** covers commands like it,
  with the same danger, until your next message. The reviewing model
  never approves these, and a rule saved from a card never covers them.
- **Protected files always ask you.** A write to git config or hooks, a
  shell startup file or a launch agent runs code later, so the reviewing
  model no longer approves one, and Settings no longer offers Model first
  for it.
- **Less needs to leave the sandbox.** In a git worktree, `git add`,
  `commit` and `branch` now work inside the sandbox. Temporary directories
  can be written without asking, by the file tools and by redirections.
  Cypher's own data means the running app's only, so editing a worktree
  under it no longer asks.
- **More command lines can be remembered.** A command after
  `NAME=value`, inside `nohup`, `timeout`, `nice` or `env`, or ending in
  `&` is read as that command. A rule now keeps only the commands that
  needed to leave, and Settings shows the project it applies in and the
  variables it allows.
- **Read more carefully.** The commands inside `ssh host '…'`, `xargs`,
  `exec`, `command` and `env -S` are read for what they run. Redirections
  are checked on every command, so `echo … >> ~/.zshrc` always asks you.
  git runs outside only in a repository the chat owns or the sandbox could
  not have written, and options that make git or ssh run a program
  count as dangerous.
- **A failing reviewing model stops costing you the wait.** After a sign-in
  failure (30 minutes) or two timeouts in a row (10 minutes), requests go
  straight to you, and the card says why review is paused.
- **Parallel requests ask once.** A request waiting behind a card is
  checked again after that card is answered, and a rule saved in another
  chat applies without restarting.
- **Saved rules are tidied once.** The first time the new Runtime runs,
  rules for inspections, filters such as `head -3`, one-off paths and
  `git push` are removed, and a notice lists them. The old file is kept
  beside it as `permissions.json.bak-<date>`.
- In a permission card, **O** picks Once.

Cut at build 1 on both desktop platforms. Pi Runtime moves to 1.1.0.10,
published after the desktop release, and requires 0.3.59: an older app
saving its permission settings would drop the project from a rule kept for
one project, so it would apply everywhere. iOS stays at 0.2.0 (32).
