# Cypher 0.3.69 — PDFs in Files, and forks past a prompt Pi never got

## Files

- **PDFs open in the pane.** A PDF opened on the binary info card, so
  reading one, such as a paper the agent just rebuilt, meant leaving
  Cypher. It now opens in WebKit's own viewer in the Files pane, with
  scrolling, pinch to zoom and text selection (macOS).
  - A checkout on this machine is read straight from disk, at any size;
    another device's PDF is fetched first, up to 64 MiB, with progress.
  - Refresh, and the reload when the agent changes the file, show a
    rebuilt PDF's new pages. Chat links to a `.pdf` open it there too.

## Chats

- **Fork and Restart work again after a failed send.** Cypher writes a
  prompt to the chat before it sends it to Pi, so a turn that failed or
  was interrupted before Pi recorded it left a prompt Pi never got. From
  then on every Fork and Restart in that chat was refused ("could not be
  mapped to the transcript boundary"), even at much earlier messages.
  Such a prompt is now set aside when Pi provably holds nothing in its
  place; a fork at it lands where the next prompt Pi received would, and
  a Restart of a stray last prompt clones the session without it. A chat
  where the prompt may have reached Pi under other text is still refused.

## Desktop

- Settings → Devices → Pairing names the Linux `cypher pair` commands
  next to the code it shows and in the steps for joining (from 0.3.68 on
  Linux).

Cut at build 1 on both desktop platforms. Pi Runtime stays at 1.1.0.16
and iOS at 0.2.0 (40).
