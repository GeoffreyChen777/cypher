# Cypher 0.3.23 — Subagent profiles in Settings, Cmd+F, and a cheaper Edge

## Subagents

- **Settings → Subagents edits the specialists a chat can spawn.** A subagent
  lives as `agents/<name>.md` in the target device's Pi runtime, so customizing
  one used to mean finding that directory and hand-editing frontmatter. The
  page now lists every profile the extension would discover and edits all of it
  — name, description, model, thinking, tool allowlist, read-only, and the
  system prompt — writing the same files back through the engine, because the
  files are on the device that hosts the chat.
- **Each setting is the control its type implies.** The extension matches
  `model`, `thinking` and every tool name *exactly*, so a typo did not fail: it
  produced an agent pointed at the wrong model, or silently missing a tool.
  Model comes from the target device's own `ListModels` catalog and shows the
  catalog label rather than the `provider/model` id; thinking is Pi's fixed
  `--thinking` ladder, narrowed to what the chosen model actually supports;
  tools are toggles over Pi's built-in set, with extension and MCP tools kept as
  free-form chips beside them, since Pi enumerates no catalog for those.
- **A built-in is never written.** "Customize" copies it into the user
  directory as an override, and deleting that override is a *Reset* that brings
  the built-in back rather than a delete that loses an agent. The confirmation
  says which of the two is about to happen. Identity is the frontmatter `name`,
  as the extension keys it, so renaming retires the old file only after the new
  one is safely on disk, and renaming onto an existing profile is refused.
- Frontmatter keys the app does not model survive a save verbatim, and a model
  id missing from the catalog — an offline provider, a device whose probe failed
  — keeps its raw value and says so, instead of being quietly retargeted.
- The editor opens as a modal over a scrim, like the provider forms: a heading
  naming what is being edited, the target device under it, a bounded scrolling
  body and Cancel/Save pinned in the footer. The scrim swallows clicks without
  dismissing, because the form holds a system prompt somebody just typed.

## Transcript

- **Cmd+F finds inside the open conversation.** A find bar floats in the
  conversation column — query field, an "n of N" counter, step buttons — washing
  every match amber and the active one stronger. Enter and Shift+Enter walk the
  matches, esc hands the keyboard back to the composer. Navigating parks the
  match below the titlebar, releases the bottom pin and any own-turn hold, and
  leaves a row already comfortably on screen alone, so stepping through several
  hits inside one reply does not re-snap the viewport for each of them.
- The index is per row, so a streaming commit rescans only the rows whose
  version moved. Within a row the painter resolves its own byte ranges as each
  text element is built, which is what lets the count cover rows the virtualizer
  has never built. Tool, error and slash-command chips stay out of the index:
  they render no laid-out text to wash, and counting them would promise a
  highlight nothing can paint.

## Fixes

- **Clicking Submit on a question card sends what you typed.** Picking
  pi-ask-user's freeform option opens an options-less input; Enter folded the
  text into the answer but the footer button advanced without ever reading it,
  and an empty label is not "nothing picked" — the bridge maps it to
  `cancelled: true`, so the answer was thrown away and the tool reported a
  cancellation. Every route into an answer now collects the text in one place.
- **The caret stays put while an IME composes into mixed-language text.**
  `setMarkedText:selectedRange:` reports its range in UTF-16 units measured
  inside the string it just handed over, not inside the document; both text
  inputs resolved it against the whole buffer. ASCII hid it because UTF-16 and
  byte offsets coincide there — each preceding Chinese character drifted the
  caret two bytes further right. Fixed in the composer and the code editor.
- **A finished upload stops narrating every other conversation.** The progress
  slot was never cleared and carried no chat id, so once you attached an image
  anywhere, every working spinner in every chat read "Uploading 100%". It now
  carries its owning chat and is retired on every exit path of the send.
- **A row in the Files tree is clickable across the column**, not just the width
  of its name, with the highlight drawn as an inset pill.

## Translation

- **The answer's translation streams instead of appearing at the end.**
  Translating the final answer runs after the visible answer has finished, and
  nothing was published until it was done — so the session's event stream went
  quiet, the engine parked the turn after 20s, and a translation slower than
  that window was discarded whole with no sign of it. The answer simply stayed
  in the working language.
- Frames now go out as the translation arrives: an opening frame re-states the
  text already on screen before the model is called, a keepalive re-sends the
  current rendering every 4s, and frames are throttled to the 150ms doc commit
  tick. A 120s deadline aborts the request, and detection gains a 2s timeout,
  because a keepalive that effective would otherwise hold a turn open forever
  against a provider that never answers.
- A frame carries the whole replacement for the message's text rather than the
  translation alone, so replaying one converges instead of appending a second
  copy of the answer. The 64KiB frame cap also dropped long answers silently,
  since an append frame carries the original *and* its translation while the
  extension caps only its 24k-char source.

## Edge

- **An idle client now costs about 12 billable requests an hour, against
  roughly 252 before.** The activity heartbeat — the viewport reporting which
  chat is on screen, so the Edge can suppress a push for a chat you are looking
  at — was 56% of billable traffic as a 15s HTTP beat. A presence beat already
  goes to the same object on the same cadence over an open socket, so the
  refresh rides it: 1.050 → 0.050 billable per beat. Transitions still spend an
  HTTP request, because only they need the reply carrying `readEventIds` and the
  badge. A workerd test proves both transports store identical state, so the
  saving is not bought with behaviour.
- `PUT /chat2/{id}/tail` rode the 1s snapshot tick, so a streaming chat
  published once a second; it now has a 10s floor, with the publish after the
  final change exempt so a settled chat is always exact — 9 publishes on a real
  streaming run where the old code sent ~171.
- A presence beat no longer wakes every subscribed viewport when nothing
  changed, and a relay probe that successfully finds a device alive now backs
  off too, so a live device whose beat never arrived is not re-probed forever.
- `cypher-releases` grew about 84 MB per application release and 640 MB per
  Runtime revision and had reached 86% of the R2 free tier. `release.py` now
  applies retention after a successful publish, and `prune-releases` runs the
  same pass by hand — dry by default. A key is a candidate only if it parses as
  a versioned artifact, falls outside the keep window, *and* is named by no live
  pointer, so an unrecognized key is always kept rather than always swept.
  Retention on the publish path is deliberately non-fatal.
- `cf-usage.py` reports every metered dimension against its Workers Paid
  inclusion for the current billing cycle and exits non-zero when a meter is
  projected past a threshold, so it works as a cron guard. It reports the
  *billed* Durable Object count, folding WebSocket messages 20:1 rather than
  repeating the dashboard's inflated figure.

## Development

- **The hosted development Worker is retired, not paused**, together with its
  six Durable Object namespaces and the development buckets. It drew on the same
  account allowance as production, its guard distorted exactly the billing
  numbers it was used to measure, and its room allowlist had filled permanently.
  A development-profile engine now defaults to `http://127.0.0.1:27640`, the
  port `edge`'s `dev` script binds; `CYPHER_DEV_EDGE_URL` still points one at a
  self-hosted staging server, fenced so it can never be the production Edge and
  plaintext only to loopback. See `docs/local-edge.md`.

## Pi Runtime 0.86.0.3

- The translation extension publishes the answer progressively and re-sends the
  current rendering every 4s, so a slow translation keeps the turn alive instead
  of racing the engine's park window. Its frames carry the whole replacement for
  the message text, which is what makes replaying one idempotent. Pi itself is
  unchanged at 0.86.0; only the bundled extension moves.

## iOS 0.2.0 (15)

- The activity heartbeat rides the presence socket here too, and repeats outside
  the only window the Worker reads them in — foreground *and* on a matching chat
  — stop outright.
