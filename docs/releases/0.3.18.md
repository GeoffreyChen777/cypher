# Cypher 0.3.18 — Hangs, heartbeats, and per-platform releases

## Reliability

- **The headed app no longer hangs silently.** The embedded engine ran on
  gpui_tokio's two-worker runtime, shared with the IPC server, presence, sync,
  agent runs and updates. Two blocked workers took the whole engine down with
  no panic and no log line: presence went dark and `cypher sync` timed out
  while the process stayed alive. The engine now owns a four-worker
  `cypher-engine` runtime, and every synchronous call that can take more than
  a few milliseconds — keychain access (bounded at 15s, so an unanswered
  consent dialog can't block forever), Pi Runtime unpacking, MCP config,
  update staging, directory removals, registry snapshots — runs off it.
- **A Linux headless engine could deadlock against itself.** The chat2 client
  held its state lock while persisting, which exported the Loro doc, which ran
  the doc host's commit hook, which took the same lock. Loro parks every other
  thread committing to that doc, so presence, IPC, sync and the live run all
  stopped together. Two rules now hold: the client never calls a sink method
  that touches the document under its own lock, and a Loro subscription only
  forwards bytes to a channel.
- **Terminals, forks and diffs work on project-less chats.** A chat with no
  project stores its working directory as `~`, and only the run path expanded
  it. Opening a terminal reported "Session working directory is unavailable"
  instead of a shell in your home folder, and Session Fork refused the same
  chats. Every reader that turns a chat's directory into a real path now
  resolves it on the host that owns it.

## Cost

- **Three timers, none of them user traffic, were about two thirds of the
  account's Durable Object requests.** Measured overnight with nobody using
  the app, a live session still took ~380 requests and ~1,350 row writes per
  hour just to say "still here". A joined registry room now pushes on its
  WebSocket alone instead of also spending a full HTTPS round trip per local
  mutation; every offline path keeps the HTTPS transport exactly as it was.
  The same allowance now covers roughly four users' worth of usage instead of
  under two.

## Transcript

- A settled turn that did work before answering now carries a hairline at the
  start of its answer — **"Worked for 1m 32s"** — so re-reading a transcript,
  or opening it on another device, no longer loses the time the live indicator
  showed. Entries gain a durable `completedAt`; a plain reply, a turn that
  ended on a tool, and sub-second turns stay unmarked.
- **Question panels hand over instead of flashing.** A two-stage question —
  pick an option, then the optional comment — arrives as two separate
  requests, and the panel used to fade out and back in between them. The
  answered card now holds its place and pages to the next stage in position,
  while answering the last stage closes it at once.

## Releases

- **Linux, macOS, iOS and the Pi Runtime now publish independently**, each
  from its own workflow and its own channel, with its own build number. One
  platform can be re-cut without disturbing another, and the Runtime ships
  without an application release. Clients released before the split keep
  updating: the shared pointers move only to a version every desktop platform
  covers at build 1, and are never rolled back.
- Settings → Devices and `cypher update` treat a Runtime-only release as an
  update, so a curated-package refresh reaches the fleet on its own.

## Files

- The folder browser and file index no longer stat inside Apple Music and
  Photos libraries.
