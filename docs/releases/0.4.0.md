# Cypher 0.4.0 — Workspaces

## Workspaces

- **A workspace is an agent with a goal.** Give it projects and an
  instruction; its agent plans the work, does it in a project itself or
  starts sessions to do it, watches them and reports back in the
  workspace chat. Switch between Projects and Workspaces from the logo
  at the top of the sidebar.
  - A plan waits for your approval before it runs, and its steps, timing
    and result show on the work page. Stop ends it; finished work can be
    deleted.
  - A workspace runs on one desktop device, chosen when it is created.
    That device must be on 0.4.0: older versions are listed as "Needs
    Cypher 0.4.0 or newer".
  - New workspaces start with Coordinate on, and pick a robot face or
    another avatar.
- **Needs you.** One inbox for the decisions waiting on you: plans to
  approve, questions to answer and notes held for review.
- **Routines.** Prompts that run on a schedule, or once at a set time
  for a reminder, with the model you choose. Each result arrives in the
  workspace chat as a card. A routine that would need an answer from you
  stops and says so instead of waiting.
- **Notebook.** Each workspace keeps notes its agent can read, search
  and edit, and you can add your own from the + in its header.
- **Shortcuts.** Ask a workspace's agent to turn a workflow into a
  button at the bottom of the sidebar; one click runs it again.
- **The agent can act for you.** When asked, the workspace chat runs a
  routine now, deletes one or stops work, and reads the workspace's
  activity log.

## Memory

- **Agents remember.** What they learn about you, each project and each
  workspace is kept as files you can read and edit in Settings → Memory.
  A nightly pass tidies them.
- A write the agent isn't sure of is asked about in its chat with Save /
  Don't save. Agents save what you ask them to remember at once, and look
  in memory before searching old chats.

## Connections

- **Workspaces can ask each other.** Invite a teammate with a code, or
  paste theirs. Their workspace can then ask yours questions, read-only
  and within what you allow.
  - Replies are Auto, Review (each answer waits as a draft for you to
    approve, edit or decline) or Off.
  - Before an answer leaves your device, strings that look like secrets
    are redacted. This is a safety net, not a guarantee.

## What's new

- After this update a short card walks through the new features once.
  New installs skip it.

## Names

- "Workspace" now means only the new feature. The synced account is the
  *synced account* (or *local mode*), the permission level that edits
  project folders is **Edit project** (`/permissions project`;
  `workspace` still works), the tile layout group is **Layout**, and the
  settings group over Devices and Archived is **Account**.

## iPhone and iPad (iOS 0.4.0)

- Home switches between sessions and workspaces at its top left, and
  the workspace list shows an amber count of what needs you.
- A workspace's chat, board, routines, notebook, settings and memory
  work on the phone, including approving plans and answering reviews.

## Fixes

- With Only paired devices on, a message of your own was now and then
  refused as unsigned: a host could read a queued command before its
  signature was in place. The command is now queued in one step.

## Pi Runtime 1.5.2.1

- **Pi 1.5.2** (from 1.1.0), with pi-claude-bridge 0.12 (Claude Code
  2.1.321: Fable 5.2 and Mythos 5.1/5.2 with 1M context), pi-goal 0.55,
  pi-ask-user 0.17.2 and pi-codex-tools 0.4.1.
- A Claude chat resumes its Claude Code session after an edit, rewind or
  fork instead of rebuilding it, so it keeps the prompt cache and
  earlier thinking. Tool calls Claude Code rejects no longer hang the
  turn.
- The grep tool's `glob` is relative to the folder it searches, not the
  one Pi started in, so `path: "repo"` with `glob: "src/*.ts"` now
  matches.
