# Cypher 0.3.21 — Restart a conversation from any message

## Transcript

- **Hovering a settled message offers a restart beside the fork.** A fork
  answers "what if I had asked this differently" by leaving the chat — it mints
  a second session and a near-duplicate sidebar row to keep straight. The more
  common intent is to take back the last few turns and carry on where you
  already are. On a user message the restart deletes that message and everything
  after it and hands its text back to the composer, ready to be rewritten; on a
  reply it keeps the reply and deletes what follows. The chat id, its tab, its
  sidebar row and its doc lineage are untouched: only the transcript gets
  shorter, and the chat's Pi session is re-pointed at a truncated copy of
  itself, so the next message continues with the model's context cut to the same
  place.
- **Deleting messages is permanent, so the button arms before it acts.** The
  first click tints it and its tooltip names the cost — "Click again to delete
  this message and 3 messages after it" — and the arm expires after four
  seconds, so a button left hot never makes the next stray click destructive.
  The newest message has nothing after it, so the affordance is inert there
  rather than spending a session on a no-op.
- The restart is Pi-only and owned by the device hosting the session, exactly
  like the fork: a chat hosted on another device restarts on that device.
  Side chats, subagent chats, non-Pi chats and a chat with a turn still running
  say so in the tooltip instead of offering a click that cannot work.

## Under it

- The boundary is the fork's, unchanged, because it is the same question: which
  prefix the pi session can represent. The engine drives the same
  `--no-extensions` helper against a byte snapshot of the session file — never
  the live client, never the source bytes — so the pre-restart session survives
  on disk. What differs is where the result lands.
- The transcript is truncated in one commit, so every watcher sees one shorter
  transcript rather than a shrinking sequence of them, and the chat row and the
  live resume cache are re-pointed together: leaving either stale would resume
  the pre-restart session on the next send and bring the deleted turns back. A
  transcript that moved while the helper was working (a queued command draining,
  a remote device appending) refuses the cut rather than applying a plan that no
  longer describes it.
- A restart that empties a chat also drops the `.pre-chat2` rollback copy, which
  boot-time transcript salvage would otherwise use to restore exactly the
  history that was just removed.

Cut at build 1 on both desktop platforms. The Pi Runtime stays on 0.86.0.2 and
iOS on 0.2.0 (14); nothing in this release touches either.
