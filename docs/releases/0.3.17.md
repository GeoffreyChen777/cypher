# Cypher 0.3.17 — Quick chats, pins, fleet updates, and Claude web search

## Sidebar

- **Quick chats:** a new button beside the sidebar's **+** opens a device
  picker and starts a session in a throwaway folder on that device
  (`<temp>/cypher-scratch/<chat id>`) with no project. Deleting the session
  deletes the folder; the host only removes a folder it minted for that chat.
- **Pin** projects and sessions from their context menus. Pinned projects lead
  the sidebar, pinned sessions lead their project, and pins sync across devices.
- **View menu:** filter the sidebar by device and sort by new activity, name,
  device or creation date, ascending or descending. The choice is remembered.
- **Project icons and colours:** click a project's glyph to pick from 21 icons
  and 9 colours (or reset). Both sync.

## Devices

- Settings → Devices checks every online device for a newer release and offers
  **Update** per device, or **Update all**. Linux services swap and restart
  themselves; Macs swap their app bundle and relaunch. A device with active
  runs or open terminals refuses until idle, or until you pick **Update
  anyway**. Rows show checking / available / updating / restarting and resolve
  when the device reports its new version. iOS updates through TestFlight and
  is not included. Remote Mac updates require the target Mac to already run
  0.3.17 or newer.

## Claude and web search

- Settings → Providers → Claude gains a **Manage** dialog (and a ••• menu) with
  the Claude Code CLI status and a **web search fallback**. Cypher can't drive
  Claude Code's own web search yet, so while a Claude Code model is selected,
  `web_search` runs through another model. The default is **Automatic**, which
  ranks a search-capable model from that device's own catalog; you can pin one
  instead. The setting is per device.

## Linux

- `cypher update` now works after any installation, not only the curl one: a
  binary outside the managed `~/.cypher/app` layout is moved into it,
  `~/.local/bin/cypher` is linked there, and a service that ran the old path is
  repointed. Only source checkouts stay report-only.
- One `cypher update` now brings the whole device current: release, service
  restart, and the newest Pi Runtime. It refuses to restart under live runs
  unless you pass `--force`; `--check` reports both and exits 1.
- Automatic updates default **on** for Linux services (`CYPHER_AUTO_UPDATE=0`
  disables). `cypher status` shows which applies.

## Engine

- Every Pi Runtime activation — including the six-hourly background update —
  now reloads model/command discovery and recycles parked sessions, so a
  long-running host no longer serves the previous bundle's catalog.
- Bundled Runtime packages are reconciled at engine boot, so a bundle activated
  by an older engine gets its new packages enabled once (this is what left
  pi-claude-bridge disabled, hiding Claude models).
