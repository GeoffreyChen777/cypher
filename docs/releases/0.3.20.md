# Cypher 0.3.20 — Questions that answer cleanly, shorter tool groups, a detector that reads mixed messages

## Questions

- **The sessions sidebar says which session is waiting on you.** A session that
  stopped to ask a question looked exactly like one that had simply gone quiet.
  The status corner now marks it, in the slot the spinner and the timestamp
  already share, so nothing about the row's width moves as the state changes.
- **An answered question card goes on the click that answered it.** The card
  used to stay mounted but inert until the transcript proved nothing more was
  coming — options lost their click and hover and went muted — so a click landed
  on a card that then sat there for a full engine round trip. Inert is
  indistinguishable from frozen. The card now retires on the click and the
  composer comes straight back.
- **The panel no longer flashes between stages.** A multi-stage question whose
  stage released early faded its card out, faded the composer in, and faded the
  next card back in about 200ms later; the fade pair *was* the flicker. A card
  mounting right after an answer now swaps in without an entrance fade, and so
  does the composer handed back by an answer. Answering twice is impossible by
  construction rather than by an inert flag.

## Transcript

- **An open tool group shows its most recent calls, not all thirty.** While a
  turn is streaming, its trailing group is auto-open, so a long run of tools
  grew downward under the composer and pushed the answer you were waiting for
  off the screen. An open group now renders its last few chips and folds the
  older ones behind one row — "Show 7 earlier tool calls" — on the same guide
  rail. The cap is a client setting (Appearance → Chat interface, "Tool calls
  shown per group"), default 5, and stepping below 1 reads "Show all" and
  disables it.

## Translation

- **A Chinese message carrying English technical words is finally read as
  Chinese.** Offline language detection moves from whatlang to Lingua, built
  with Chinese and English alone. 帮我 fix 一下这个 bug came back as Turkish
  before — mixed Han/Latin text breaks trigram scoring — and an unreliable
  detection is never allowed to skip a translation request, so every mixed
  message paid for one. Worse, an unreliable detection teaches the feature
  nothing, so with the source language on *auto* a session of mixed messages
  never learned which language to translate answers back *into*: requests went
  out translated and answers came back untranslated, silently. Both are fixed.
- Text in a script neither language uses — Japanese, Korean, Russian, Arabic —
  carries no decision at all and goes to the translation model rather than being
  labelled wrongly. The settings card offers English, Chinese and Auto detect to
  match what the detector can actually judge; a language configured before this
  release keeps translating rather than being skipped.
