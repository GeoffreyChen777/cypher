# Cypher 0.3.61 — File links open in Files, a steadier progress bar, and lighter animations

## Performance

While a turn ran, Cypher redrew its whole window 30 times a second for
the spinners and the progress bar, which kept a core about a fifth busy.

- **Animations run at 20 frames a second**, and the window does a third
  less work while you watch. The fastest animation, the running tool's
  arc, still turns smoothly.
- **8 frames a second while you're in another app.** A window that is
  still visible behind another app keeps its animations, slower. A
  window that is fully covered or minimized draws nothing, as before.
- **Reduce Motion is respected.** With System Settings → Accessibility →
  Display → Reduce motion on, spinners and the progress bar hold still,
  menus and panels appear without animating, and a running turn costs
  about what an idle window does. Changing the setting applies when you
  come back to Cypher.
- **Files, Git and side chats in the side panel no longer rebuild on
  every animation frame.** They redraw only when they change.

## Chats

- **File links in replies open in Files.** Clicking a link to a file did
  nothing: a path such as `src/a.rs` or `/repo/a.rs:12` is not a web
  address the system could open. It now opens in the session's Files tab,
  revealed in the tree, which opens the dock if it is closed and reuses a
  Files tab that is already there.
  - A line in the link (`a.rs:12`, `a.rs:12:5`, `a.rs#L12`) selects that
    line and scrolls to it; a Markdown file then opens in its source.
  - Relative paths are read from the chat's project folder, and `file://`
    links and Mention in Chat links work too. A link ending in `/` expands
    the folder.
  - A file outside the project folder can't show in Files: when it is on
    this Mac, it is revealed in Finder instead.
  - Web and mail links still open in the browser and mail app. Links in
    side chats open as before.

## Progress bar

- **Finished steps stay put.** When the estimate went back because the
  agent found more work, the fill dropped behind the steps already
  passed, and dots for the steps still to come landed on top of them, so
  the passed dots showed in several shades of grey. A step's dot now
  never moves once it is passed: each reading changes only the fill, the
  current step and the steps ahead, and the fill never drops behind
  where the current step began. The model is told which steps are done,
  so it no longer lists them again as steps ahead. A dot that would
  overlap the one after it is left out.
- **No reading while nothing changes.** A turn waiting on one long step
  asked the small model again every half minute anyway. A reading is now
  only requested once the agent has written, run, finished a step or
  updated its plan since the last one, so the bar keeps its reading
  through a long wait. A reading that fails is retried on the next check.

Cut at build 1 on both desktop platforms. Pi Runtime stays at 1.1.0.11 and
iOS at 0.2.0 (34).
