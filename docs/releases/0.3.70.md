# Cypher 0.3.70 — One device list, receive-only devices, signed messages

## Devices

- **One list.** Settings → Devices listed every machine twice: once with
  its platform and version, again under Pairing. Each machine now has one
  row with its key and what it may do, and paired devices that never
  showed up before, such as the iPhone, appear too. Rename, Copy device
  ID, Unpair and Remove from account moved into the row's `•••` menu;
  Add a device sits at the top of the list, and Only paired devices
  below it.
- **Receive-only devices.** A device with full control can make another
  receive-only from the access pill on its row. Your other devices can
  still open its sessions, send it messages and control it; it can't
  control them, add or remove devices, or change these settings. Use it
  for machines you don't fully trust, such as a shared server.
  - It needs Only paired devices, which turns on with it and stays on
    while any device is receive-only.
  - A receive-only device says so at the top of its own Devices page.
  - Every device must be on 0.3.70 (iOS 0.2.1) for the restriction to
    hold: earlier versions can't read the updated device list and don't
    enforce it.
- **Signed messages.** Messages sent to a chat that runs on another
  device are now signed by the device that sent them. With Only paired
  devices on, a device runs only messages signed by one of your paired
  devices with full control, so a stolen sign-in or a tampered server
  can't send work to your machines. A message that was changed after it
  was sent is never run. Messages from a device that isn't updated yet
  are refused while the switch is on: update it, or send again from an
  updated device.

## Settings

- **Codes copy with a click.** The pairing code, the `cypher pair join`
  command next to it and the ChatGPT or Claude sign-in code are shown in
  a block that copies on click, like the GitHub sign-in code.

Cut at build 1 on both desktop platforms, with iOS 0.2.1 (41). Pi Runtime
stays at 1.1.0.16.
