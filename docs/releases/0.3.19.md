# Cypher 0.3.19 — Two languages in one chat, and code that isn't drawn over itself

## Translation

- **A chat can run in your language and the agent's at the same time.**
  Settings → Agents grows a **Message translation** card: pick the translation
  model and both languages from the device's own Pi catalog, and enable it per
  session model rather than through one global switch — only a chat whose model
  is on that list is translated. The request goes out in the working language
  and the answer comes back in the language you write in.
- **The model's context is untouched.** Translation is a Pi extension, so it
  applies to every Pi entry point, and the rendered answer is replaced (or
  appended below a rule, if you prefer both) through a side-band event. Pi keeps
  its own message, so the transcript the agent reasons over, and the tool calls
  inside it, stay exactly as they were produced.
- **A message already in the destination language costs nothing.** Language
  gating runs offline: only a *reliable* detection may skip a request, so
  anything uncertain still falls through to the model rather than being silently
  left untranslated.
- Saving a setting takes no device write lease and does not recycle Pi sessions
  — the extension re-reads its settings on every message.

## Transcript

- **`===` no longer paints over the code to its left.** The bundled Geist Mono
  1.700 exposes its coding ligatures through default-on `liga` as a plain
  three-glyph substitution, but the glyph is drawn for the spacer construction
  upstream drives from `ss11`: one cell of advance, with ink reaching two cells
  *backwards*. `return model.api === a` therefore shaped to 13 glyphs where the
  grid wanted 15 — the three-bar glyph landed on the first `=`, overlapped the
  text beside it, and pulled the rest of the line two cells back. Every
  monospace run in the app now ships those features off, so `===`, `--`, `->`,
  `!=` and `|>` render as typed in fenced blocks, inline code, diffs, file
  paths, shortcut chips and the terminal.

## Pi Runtime 0.85.1.10

- **A message is translated against the turns that came before it.** A word with
  several readings — 接口 as interface or endpoint, `commit` as git or promise —
  was previously settled by nothing at all, and a message with no noun in it
  (*try again*, *why did it fail*) left the model to invent the referent the
  agent would then act on. Each request now carries a short reference block of
  recent turns, quoting **both** languages of each one so the second mention of
  a term is rendered the way the first was.
- The block is text only — your messages and the model's final answers, never
  tool calls, tool output or thinking. Those are the bulk of a coding
  transcript's tokens, they carry no word sense, and the translation model is
  often a different provider than the coding model. It is bounded at two
  exchanges and skipped for a message already long enough to carry its own
  referents.
- The translation model is now asked for the translation and nothing else: no
  JSON envelope, no preamble, no label, and no code fence wrapped around the
  answer.
